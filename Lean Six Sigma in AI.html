Module 3: Create Flow

What is flow?

Work moves smoothly from one step to the next.

Poor flow

Request→Waiting→Approval→Waiting→Development→Waiting→Testing→Rework

Improved flow

Request→Analysis→Development→Testing→Release

How to improve flow

Remove unnecessary stepsReduce waiting timeReduce handoffsStandardize processesAutomate repetitive workIdentify bottlenecks

Module 4: Establish Pull System

What is pull?

Push

Produce based on forecast or assumption.

Development builds many features→Customer may or may not need them

Pull

Start work based on actual demand.

Business requirement→Prioritize→Develop→Deliver

IT example

“We have capacity, so let’s build this feature.”

“There is a validated business need, so let’s prioritize this feature.”

Module 6: Introduction to Six Sigma

What is Six Sigma?

Reducing variation and defects, using data.

Lean asks

“Where is the waste?”

Six Sigma asks

“Why is the process producing defects or variation?”

Lean + Six Sigma = Faster + Better + More Consistent

Module 6: Introduction to Six Sigma

D

Define the problem.

M
Measure

Collect reliable data.

A
Analyze

Find the root cause.

I
Improve

Implement solutions.

C

Make sure the improvement continues.

Example: customer application takes 5 days

Define
Processing is too slow.

Measure
Average time is 5 days.

Analyze
Manual approval causes 2 days of delay.

Improve
Automated approval routing.

Control
Monitor processing time monthly.

Module 7: Cost of Poor Quality

What is COPQ?

Cost of Poor Quality is the cost caused by defects and failures.

ReworkCustomer complaintsRefundsProduction errorsSystem downtimeRepeated testingSupport ticketsData correctionLost productivity

IT example

A system defect causes 100 customer transactions to fail. The cost is not only the developer’s fixing time.

Developer time+Support+Business operation+Customer impact+Revenue impact

Module 10: Lean Six Sigma 4.0

Example improvement project

Problem

Customer request processing takes too long.

Current situation

  • Average processing time: 5 days
  • Manual approval
  • Duplicate data entry
  • Frequent follow-up emails

Root causes

  • Manual workflow
  • Lack of process visibility
  • Multiple handoffs
  • No automated validation

Proposed improvement

  • Automated workflow
  • API integration
  • Automated validation
  • Dashboard monitoring

Target: 5 days → 2 days

Continuous improvement mindset

Traditional mindset

“This is how we have always done it.”

Continuous improvement mindset

“Can we do it better?”

Ask

  1. What is the problem?
  2. What is causing it?
  3. What does the data tell us?
  4. What waste can we remove?
  5. Can we automate it?
  6. How do we measure improvement?
  7. How do we prevent the problem from coming back?

My role as a Lean practitioner

My role is not simply to find problems. It is to understand the process, identify waste, use data to find the root cause, work with stakeholders to improve the process, and make sure the improvement is sustainable.
